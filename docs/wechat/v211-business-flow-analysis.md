# 页面都在，流程却走不通：断点从不报错

接手一个存量系统最怕什么？不是代码烂，是**动线断了不吭声**——
列表页、详情页都好好在线，点"编辑"却发现这个页面根本不存在；
表单提交了，跳转回来参数全丢。没有报错、没有红叉，只有用户默默流失。

v2.11 把"梳理动线"从口头讨论变成可核对的方法论：

- **FLOW 业务动线**：从路由、页面、接口反向重建每条业务流程，
  每个流转节点登记为 OP 操作点，**带代码位置证据**——不靠猜
- **BREAK 断点定位**：跳转缺失 / 参数丢失 / 状态不衔接，逐一登记成断点清单
- **缺失页面详细设计**：不是记个 TODO 就完事，而是逐个补齐布局、字段、交互设计
- **评审后执行**：动线完整性先过 v2.10 共识收敛门禁，共识清零才进开发

断点清单不是问题清单，是**设计输入**：先补动线，再谈写代码。
产出的动线分析文档还直接喂给 v2.12 的测试规划——分析、设计、测试一条线拉通。
