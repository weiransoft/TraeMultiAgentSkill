# 用例全绿，功能却漏测：覆盖率的盲区在哪？

"用例全过了"和"功能都测到了"是两回事。
覆盖率统计的是代码行——你根本没为那个"确认删除"按钮写过用例，
它就永远不会红给你看。

v2.14 补上最后一块拼图，两件事：

**一、功能覆盖驱动。** 规划期先产出 FUNC-* 每页功能清单：逐页列全功能项，
分 interactive / form / display / nav / branch 五类，每项带 `文件:行号` 证据；
交互和表单类**必须 P0 覆盖、禁止豁免**。收尾时 finalize 从执行记录里
**现算** FUNC × PASS 断言矩阵——feature_gate 不信任任何自报覆盖率；
清单原件 SHA256 锚定，执行中途删功能项"移动球门"，哈希对不上直接 FAIL。

**二、缺陷必须有下文。** 执行期 `error --suspected-bug` 只是信号，
`defect` 子命令生成跨 run 全局工单：open → fixed 必须登记修复 commit，
→ closed 必须回归 run 关联用例**全 PASS** 才放行，再犯 reopen 强制写理由。
漏登一张工单，整体 gate=FAIL。

至此收尾是**四道闸**：P0 × data_gate × feature_gate × 缺陷登记闸，"与"关系，
一道不过不放行。19 个端到端用例 + 前两版全量回归 50 passed，纯标准库零依赖。
