# 发布前的最后一关：四道闸，一道不过就不放行

`finalize` 是整个浏览器测试闭环的收尾闸口。v2.14 之后是四道：

1. **P0 门禁**——P0 用例通过率必须 100%，v2.12 起就有
2. **data_gate**（v2.13）——数据断言失败、声明的 DB 校验没跑、
   数据通道故障，全部计入 FAIL
3. **feature_gate**（v2.14）——功能清单覆盖矩阵现算，
   interactive/form 有缺口就拦下，清单被篡改直接拦下
4. **缺陷登记闸**（v2.14）——执行期每一个 suspected_bug 信号，
   都必须有对应的 DEF-\* 工单，漏登一张，整体 FAIL

注意：四道闸是"**与**"关系。

P0 全绿但漏登一张缺陷工单？FAIL。
缺陷全闭环但功能清单有个按钮没测？FAIL。
数据全对但有人偷偷删了清单里两个功能项？SHA256 对不上，FAIL。

单人自测最容易骗过自己的，就是"应该没问题了"这六个字。
所以闸必须是**别人定的规则 + 机器执行**，而不是自己给自己开绿灯。

绿灯是挣来的，不是声明的。
