# 让 AI 评审 AI 的方案，谁会认真挑刺？

多智能体协作最容易自欺的一环，就是"方案评审"：
写方案的是一个模型，评审的还是同一个模型——它当然觉得自己的方案完美，
等于自己给自己发奖状。

multi-agent-team v2.10 把评审做成**结构化的交叉火力**：

- **五视角评审团**：架构师盯边界与技术债、独立开发者挑可实现性与隐藏坑、
  测试专家审可测性与边界条件、产品经理对需求偏差与遗漏场景——
  各审各的，**独立出报告，互不通气**
- 每条问题按 **BLOCKER / MAJOR / MINOR** 分级，不许含糊
- 意见冲突不掩盖：进入**分歧交锋**，逐条辩论，理由必须可检验
- 最后收敛成**共识表**：每条问题落为 共识 / 异议保留 / 驳回——
  异议保留也必须记录在案，谁保留、为什么，全可追溯

放行门禁只有一条硬规矩：**共识问题清零 + BLOCKER 清零，缺一不放行。**

这套协议后来成了整个 skill 的基建：v2.12 用它评审测试四件套，
v2.13 用它评审 DC 数据契约，v2.14 用它评审 FUNC 功能清单——
评审对象在变，"不共识、不开发"的规矩没变。
