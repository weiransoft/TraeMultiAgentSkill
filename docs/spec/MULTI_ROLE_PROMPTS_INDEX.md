# 多角色代码走读 Prompt 模板

> **版本**: v2.6 | **更新日期**: 2026-06-17

## 概述

本目录包含用于多角色代码分析的 prompt 模板。每个角色（架构师、产品经理、独立开发者、UI设计师、测试专家）都有专属的分析视角和输出格式。v2.6 新增逻辑漏洞审查专家角色和 Ponytail 决策梯评审清单。**v2.10 新增业界调研专家和 4 个方案评审角色 prompt，用于方案撰写全流程。**

## Ponytail 决策梯评审清单（v2.6 新增）

独立开发者（solo_coder）的代码分析模板已包含 Ponytail 决策梯评审清单（第 6 节），涵盖：

- **6.1 决策梯合规检查**: YAGNI / 标准库优先 / 平台原生 / 复用现有 / 一行优先 / 最小可行
- **6.2 16 条红线检查**: 输入校验 / 错误处理 / 安全 / 无障碍 / 用户要求 / 硬件校准 / 真实业务逻辑 / 需求文档功能 / 非平凡逻辑 / 并发安全 / 真实错误处理 / 日志审计 / 配置密钥 / 事务边界 / API 契约 / 隐私数据
- **6.3 债务台账检查**: 债务标记 / 升级路径 / 债务腐烂
- **6.4 需求追踪检查**: 需求标记 / 实现覆盖 / 无幽灵代码

详细指南见 `docs/guides/PONYTAIL_GUIDE.md`。

## 使用方法

### 在 Agent 流程中使用

当需要多角色分析时，按照以下流程调用：

```
1. 收集项目基本信息（项目扫描）
2. 分发各角色分析任务（并行执行）
3. 收集各角色的分析结果
4. 执行文档对齐
5. 生成统一代码地图
```

### 角色分析模板使用示例

```markdown
## 角色分析任务

请从 [角色名称] 的视角分析以下代码：

**项目信息**:
- 项目名称: {project_name}
- 工作空间: {workspace_name}
- 编程语言: {languages}

**代码文件列表**:
{file_list}

**请按照 {role_name} 的视角分析以下内容**:
{focused_questions}

**输出格式**:
按照 {role_template_path} 中的格式输出分析结果。
```

## 文档对齐原则

1. **共识优先**: 多个角色共同确认的信息优先保留
2. **差异标注**: 不同视角产生的差异需要明确标注
3. **互补增强**: 不同角色的分析可以互补，增强理解
4. **冲突解决**: 当冲突发生时，按照以下优先级解决：
   - 架构师视角 > 产品经理视角 > 独立开发者视角
   - 代码证据 > 推测分析
