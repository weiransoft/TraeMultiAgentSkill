# 6 个版本，把 AI 多智能体开发从"能跑"磨到"可信"

AI 写代码早已不新鲜，新鲜的是**敢不敢信它**。multi-agent-team 用 v2.9 → v2.14 六个版本回答这个问题，每一步都堵一个"自欺"的漏洞。

**v2.9 系统理解：先看懂，再动手。** 面对没文档、没源码的黑盒系统，SU 能力全程只读反向理解——Playwright 登录 + 图式 BFS 遍历，危险按钮零点击，网络层拦截一切非 GET；MySQL/Redis 只读内省带白名单双护栏、采样逐值脱敏；UI↔API↔DB 关联必须有数值证据。脚本层零 LLM 调用，结论由 LLM 按契约回填、CLI 收口；依赖缺失诚实降级，绝不拿假数据冒充。

**v2.10 共识收敛：不让 AI 自己给自己发奖状。** 方案放行前过五视角交叉评审——架构师、独立开发者、测试专家、产品经理各审各的、独立出报告，问题按 BLOCKER/MAJOR/MINOR 分级，分歧逐条交锋，收敛成共识表，异议保留也记录在案。硬规矩：共识问题清零 + BLOCKER 清零，缺一不放行。

**v2.11 业务动线分析：断点从不报错。** 页面都在，流程却走不通——FLOW 动线从路由、页面、接口反向重建业务流程，每个 OP 操作点带代码证据；跳转缺失、参数丢失逐一登记 BREAK；缺失页面补齐布局、字段、交互设计，先过评审门禁再进开发。

**v2.12 浏览器测试闭环：说"测过了"，拿出证据。** 测试四件套先过评审，再在 agent-browser、Trae 内置浏览器、Chrome DevTools MCP 三宿主逐一执行；每步 step/assert/shot 结构化落盘，断言必须有实际值、截图必须真实存在，P0 通过率不到 100% 不放行。

**v2.13 数据校验闭环：数据库说落对了才算。** DC 数据契约把表单→API→DB→回读全链路映射逐项钉死，动作前后 DB 快照行级 diff；UNIQ/守恒/状态机等五类业务规则由自研解析器求值（非 eval），DB 通道只读护栏，data_gate 把关。

**v2.14 功能覆盖 × 缺陷台账：绿灯是挣来的。** FUNC-* 每页功能清单当覆盖分母，交互/表单必须 P0 覆盖禁止豁免；finalize 现算覆盖矩阵，清单 SHA256 锚定防"移动球门"；疑似缺陷必须成工单——fixed 登记 commit，closed 要回归全 PASS。收尾四道闸"与"关系，一道不过不放行。

六个版本一条主线：**不信任任何口头声明，一切结论必须有机器可核验的证据。**
